# 场景清单：八个行业，一套基础设施

> 每个场景都是**可验证**的：给定输入必然得到同一结论摘要（`verify` 会重放比对，不一致就 FAIL）。

```bash
workagent cases .                                   # 列出全部场景
workagent run --case <ID> --input <文件> .           # 运行
workagent verify --all .                            # 全部场景复现校验
```

## 总览

| ID | 行业 | 形态 | 模型 | 复现等级 | 规则来源 |
|---|---|---|---|---|---|
| `salary_tax` | 人力资源 | 测算型 | 无 | **L3** | 《个人所得税法》7 级累进预扣率表 |
| `loan_dscr` | 金融 | 测算型 | 无 | **L3** | DSCR / 利息保障倍数标准公式 |
| `spc_control` | 制造业 | 核验型 | 无 | **L3** | Western Electric / Nelson 8 条判异准则 |
| `pin_conflict` | 嵌入式 | 核验型 | 无 | **L3** | MCU 资源分配一致性规则集 |
| `bid_quote` | 建筑工程 | 测算型 | 抽取 | L3 / L2 | 工程造价惯例（管理费/利润/风险预备金） |
| `expense_audit` | 财务 | 核验型 | 抽取 | L2 / L1 | 企业费用报销制度（示例阈值） |
| `lab_report` | 医疗 | 核验型 | 抽取 | L2 / L1 | 成人常见参考区间（示例值） |
| `point_table` | 工业自动化 | 核验型 | 抽取 | L2 / L1 | Modbus 寻址与数据类型规则 |

**四个 L3 场景完全不依赖模型** —— 同样的输入，在任何机器、任何时间，结论摘要都一样。

## 每个场景做了什么

### 人力资源 · 工资薪金个税测算（`salary_tax`）
按累计预扣法逐月计算应纳税额，输出每月明细与全年合计。
输入 12 个月工资、三险一金、专项附加扣除 → 全年个税与**实际税负率**。
规则来源：《个人所得税法》居民个人综合所得预扣预缴 7 级超额累进表。

### 金融 · 项目贷款偿债能力（`loan_dscr`）
`DSCR = (净利润 + 折旧 + 摊销 + 利息) / (本金摊还 + 利息)`，另计利息保障倍数。
阈值（1.25 / 1.10）**写在输入里而不是代码里** —— 不同机构政策不同，硬编码是错的。

### 制造业 · SPC 控制图判异（`spc_control`）
对一串测量值执行 8 条判异准则，指出**具体哪一点违反了哪条**。
R1~R4 判"失控"，R5~R8 判"预警"。中心线与西格玛可用 I-MR 法自动估计（MRbar / 1.128）。

### 嵌入式 · 资源冲突检测（`pin_conflict`）
引脚复用、保留调试口、优先级重复、优先级越界、DMA 通道争用、引脚命名格式。
**冲突就是 bug，编译期就能验真，规则完全确定。**

### 建筑工程 · 投标报价测算（`bid_quote`）
支持两条路径：结构化明细直接算（L3），或自然语言描述经模型抽取后算（L2）。
两条路径共用同一个执行体 —— **模型只负责把"120 吨钢材一吨 4850"变成结构化数据**。

### 财务 · 报销单合规审核（`expense_audit`）
模型把报销说明读成明细；代码做单笔限额、类别限额、时限、发票号、合计一致性检查。

### 医疗 · 检验报告异常判定（`lab_report`）
按性别区分的参考区间判定，危急值单独标记。
> ⚠️ **参考区间为示例值，本结论不构成医学诊断。** 实际以检验科报告单标注为准。

### 工业自动化 · 通信点表核对（`point_table`）
地址区间重叠、数据类型与寄存器数量、量程倒置、地址越界、缺单位、非法功能码。
**含 Modbus 参考地址归一化**（`40001` → 偏移 0）——现场点表普遍写参考号，不归一化会大面积误判。

## 加一个新场景要做什么

1. 建目录 `examples/<id>/`，写 `executor.py`、`input.json`、`boundary.json`、`README.md`；
2. 需要模型抽取的，再加 `prompt.md` 和 `input.natural.json`；
3. 在 `agent.yaml` 的 `execution.cases` 里登记一条；
4. `workagent check .` 会校验文件齐备，`run` 跑一次建立基线，`verify --all` 确认可复现。

## 执行体契约

```text
输入: argv[1] = 输入 JSON 路径（可能是富化后的 {"input": ..., "llm": {...}}）
成功: 退出码 0，stdout 输出 {"output": {...}}，纯 ASCII
失败: 退出码非 0，stderr 给出 BOUNDARY_VIOLATION 原因
```

输出建议包含：`subject`、`verdict`、`conclusion`、`findings`、`metrics`、`confidence`、`risks`。
